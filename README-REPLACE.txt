  تحديث أور پاي AurPay — 5.zip
  (تخزين دائم بنقرة واحدة + إصلاح خروجك التلقائي ورسالة PIN)
════════════════════════════════════════════════════════════

ماذا كان يحدث؟

  سويت حساب جديد ← دخلت عليه ← بعد ثانيتين طلعك للشاشة
  الرئيسية، ولما رجعت تسجّل الدخول قال لك «PIN غلط» وأنت
  كاتبه صح.

  السبب: على Vercel كل نسخة من الخادم لها ذاكرتها المنفصلة.
  حسابك انضاف لذاكرة نسخة (A)، وأول طلب بعده وصل لنسخة
  ثانية (B) ما تعرف حسابك ← ردّت 401 ← الواجهة أخرجتك.
  ولما حاولت تدخل من جديد، النسخة اللي ردّت عليك ما فيها
  حسابك أصلًا، فرجعت لك رسالة «البطاقة أو PIN غير صحيح» —
  وهي مو صحيحة، الرسالة كانت مضلّلة.

ماذا يصلح 5.zip؟

  ✚ تخزين دائم بنقرة واحدة داخل Vercel نفسه (Blob):
     ما عاد تحتاج حساب Turso ولا تنسخ أي توكن — كل شي
     من لوحة Vercel مباشرة (الخطوات تحت).

  ✚ حماية الخروج التلقائي: أي طلب يصل لنسخة ما تعرف
     حسابك يسحب أحدث حالة من التخزين المشترك ويعيد
     المحاولة قبل ما يرد 401 — فما يطلعك ثاني مرة.

  ✚ رسائل صادقة بدل «PIN غلط»: إذا كانت النسخة على
     Vercel بدون تخزين، رسالة الدخول راح تقول لك صراحة
     «البطاقة غير مسجّلة على هذا الخادم» + شريط تنبيه
     ذهبي أعلى الصفحة يشرح لك السبب والحل.

  ✚ /api/health يعرض وضع التخزين الحقيقي بعد التحميل:
       "db": { "mode": "blob"  }  ← التخزين الدائم شغّال
       "db": { "mode": "turso" }  ← إذا كنت مفعّل Turso سابقًا
       "db": { "mode": "memory"} ← ما فعلت التخزين بعد

───────────────
خطوات التطبيق
───────────────

1) فك ضغط 5.zip داخل مجلد المشروع (نفس مستوى package.json)
   واختر «استبدال / Replace» لكل الملفات.

2) ارفع التحديث:

       git add -A
       git commit -m "fix: zero-config Blob persistence + auth resync"
       git push origin main

3) من Vercel: Deployments ← آخر صف ← قائمة ⋯ ← Redeploy.

───────────────
تفعيل التخزين الدائم (٤ نقرات — كلها داخل Vercel)
───────────────

  ★ ما تحتاج تسجيل بأي موقع خارجي، ولا نسخ أي توكن ★

  1) افتح مشروعك في لوحة Vercel ← تبويب Storage
     (من القائمة الجانبية لمشروعك).

  2) اضغط Create ← اختر Blob ← خلّه Private (الأفضل)
     ← سمّه مثلًا aurpay ← اضغط Create.

  3) اربط المخزن بنفس المشروع (Connect to project) —
     متغيرات البيئة تنضاف تلقائيًا، ما تنسخ شي بيدك.

  4) ارجع لتبويب Deployments ← قائمة ⋯ ← Redeploy.

  5) افتح رابط موقعك + /api/health — لازم تشوف:

       "db": { "mode": "blob" }

     إذا شفت "memory" يعني الخطوة 3 أو 4 ما تمت —
     راجعها ثم Redeploy مرة ثانية.

  ★ بعد هاي الخطوات: كل حساب جديد يظل موجود للأبد،
    الدخول ما يطلعك ثاني مرة، وكل تحويل يخصم فعليًا
    ويثبت عبر كل نسخ الخادم ✔

  (اختياري — ما تحتاجه): إذا كنت مفعّل Turso من قبل
  4.zip، يظل يشتغل زي ما هو — Blob وTurso الاثنين مدعومين.

───────────────
للتشغيل المحلي
───────────────

       npm install
       npm run dev

  محليًا ما تحتاج أي شي — نسخة واحدة تعني الذاكرة
  مستقرة. (اختياري: تجربة نفس مسار التخزين بملف محلي:
  set URPAY_BLOB_FAKE_DIR=./db/blob-fake ثم npm run dev)

تذكير
───────────────

  * مفاتيح Groq تبقى من Vercel: GROQ_API_KEY_1 ... 5
  * حسابات التجربة: 4539123412341234 / PIN 123456
    و زينب: 4539555544441236 / PIN 123456
  * إذا ضبطت URPAY_JWT_SECRET ضبطه مرة واحدة قبل مشاركة
    الموقع (تغييره بعدين يخرج الجميع من جلساتهم).
